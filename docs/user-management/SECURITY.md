# Security policies and attack prevention\n\n## Password Security\n\n### Hashing Algorithm: bcrypt\n\n**Configuration**:\n- Salt rounds: 12 (default, configurable via Vault)\n- Algorithm: PBKDF2-SHA64 (bcrypt internal)\n- Cost factor: 2^12 = 4096 iterations\n\n**Why bcrypt?**\n- Slow by design (intentional 200-300ms per hash)\n- Resistant to GPU attacks (no parallelization)\n- Includes salt automatically\n- Adjustable cost factor for future-proofing\n\n### Password Requirements\n\n**Minimum length**: 6 characters\n- Client-side validation\n- Server-side enforcement\n- No maximum length (no DoS via very long passwords)\n\n**Complexity**: None enforced\n- Could add: uppercase, lowercase, numbers, special chars\n- Trade-off: UX vs security\n- Current spec: accept any 6+ char password\n\n### Password Change\n\n```\n1. User provides current + new password\n2. Server validates current password via bcrypt.compare()\n3. Hash new password\n4. Update database\n5. Force re-authentication on next login (optional)\n```\n\nPrevent:\n- Reuse of old password (hash comparison)\n- Too-frequent changes (rate limit to 1/day if needed)\n- Weak passwords (no dictionary check; add if required)\n\n## Brute-Force Protection\n\n### Login Rate Limiting\n\nImplemented at NGINX level (BEFORE backend processes):\n\n```nginx\nlimit_req_zone $binary_remote_addr zone=login_zone:10m rate=10r/m;\nlimit_req_status 429;\n\nlocation /api/auth/login {\n  limit_req zone=login_zone burst=5 nodelay;\n  proxy_pass http://auth_service:3001;\n}\n```\n\n**Limits**:\n- 10 requests per minute (6 seconds between attempts)\n- Burst of 5 (5 quick attempts allowed before blocking)\n- Returns 429 if exceeded\n- Blocks IP for remainder of 1-minute window\n\n### Brute-Force Detection (ModSecurity)\n\nCustom WAF rule in `app/nginx/modsecurity/custom_rules.conf`:\n\n```\nSecRule TX:FAILED_LOGIN_ATTEMPTS \"@gt 5\" \"id:1001,phase:5,action:deny,status:403,msg:'Brute force attempt'\"\n```\n\nAlternatively, application-level tracking:\n\n```javascript\n// In-memory login failure tracker\nconst loginAttempts = {}; // { ip: { count, timestamp } }\n\napp.post('/login', (req, res) => {\n  const ip = req.headers['x-real-ip'];\n  const now = Date.now();\n  \n  if (!loginAttempts[ip]) {\n    loginAttempts[ip] = { count: 0, timestamp: now };\n  }\n  \n  // Reset if window expired (5 minutes)\n  if (now - loginAttempts[ip].timestamp > 300000) {\n    loginAttempts[ip] = { count: 0, timestamp: now };\n  }\n  \n  if (loginAttempts[ip].count >= 5) {\n    return res.status(429).json({ error: 'Too many login attempts' });\n  }\n  \n  // ... validate credentials ...\n  \n  if (invalid) {\n    loginAttempts[ip].count++;\n    return res.status(401).json({ error: 'Invalid credentials' });\n  }\n  \n  // Success: reset counter\n  loginAttempts[ip] = { count: 0, timestamp: now };\n  res.json({ token });\n});\n```\n\n## 2FA Implementation\n\n### TOTP (Time-based One-Time Password)\n\n**Standard**: RFC 6238\n\n**Library**: speakeasy\n\n**Parameters**:\n- Algorithm: SHA1\n- Digits: 6\n- Time step: 30 seconds\n- Window: ±1 step (60 seconds total tolerance)\n\n**Why TOTP?**\n- No server-side state (unlike HOTP counter)\n- Synced with time (NTP)\n- Works offline (apps don't need internet)\n- Industry standard (Google Authenticator, Authy compatible)\n\n### 2FA Setup Flow\n\n```\n1. User clicks \"Enable 2FA\"\n2. Backend generates secret: speakeasy.generateSecret()\n3. Backend generates QR code: qrcode library\n4. Frontend displays QR code\n5. User scans with authenticator app\n6. User enters 6-digit code from app\n7. Backend verifies code with speakeasy.totp.verify()\n8. If valid: save totp_secret, set totp_enabled=true\n```\n\n### 2FA Login Flow\n\n```\n1. User enters email + password\n2. Backend verifies credentials\n3. If 2FA enabled:\n   - Generate tempToken (5-minute JWT)\n   - Return tempToken + requires2FA flag\n4. Frontend shows 2FA code prompt\n5. User enters 6-digit code\n6. Frontend sends POST /2fa/authenticate with tempToken + code\n7. Backend verifies code\n8. If valid: return full JWT (24-hour)\n```\n\n### Backup Codes (Optional)\n\nNot currently implemented. WHERE ...', hash);\n\n// BAD: Plaintext\nawait db.query('UPDATE user_auth SET password = ? WHERE ...', password);\n```\n\n### Secure Comparison\n\n```javascript\n// GOOD: Constant-time comparison (prevents timing attacks)\nconst match = await bcrypt.compare(inputPassword, storedHash);\n\n// BAD: String comparison (timing attack)\nconst match = inputPassword === plainPassword; // Measurable time difference\n```\n\n## GDPR Data Handling\n\n### Data Export (Article 15)\n\nUser can request Application (deepest)**\n- Business logic validation\n- Track by user ID (after auth)\n- Database queries per user\n\n## Monitoring & Alerting\n\n### Security Metrics (Prometheus)\n\n```\nauth_login_total{result=success|failed}\nauth_2fa_total{action=setup|verify|authenticate, result=success|failed}\nhttp_requests_total{status_code=401|403|429}\nmodsecurity_blocked_requests_total\n```\n\n### Alert Rules (Prometheus)\n\n```yaml\n- alert: HighLoginFailureRate\n  expr: rate(auth_login_total{result=\"failed\"}[5m]) > 0.5\n  for: 5m\n  annotations:\n    summary: \"High login failure rate (>50% failures)\"\n\n- alert: BruteForceAttempt\n  expr: rate(http_requests_total{status_code=429}[1m]) > 10\n  for: 1m\n  annotations:\n    summary: \"Rate limit triggered >10 times/min\"\n\n- alert: ModSecurityBlocking\n  expr: rate(modsecurity_blocked_requests_total[5m]) > 5\n  for: 5m\n  annotations:\n    summary: \"WAF blocking >5 requests/min\"\n```\n\nGrafana alerts forward to AlertManager → email/Slack."}
